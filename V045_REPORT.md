## 3. Phase 0 verification

The brief reported an inspection finding that `main` might still use `rng.gaussian` at
`seasonVariance` 1.5 rather than the `rng.normal` at 1.15 that the v0.4.1 report claims.

**It does not.** Verified against committed code rather than the working tree:

```
git show HEAD:src/game/worldEngine.ts  ->  rng.normal(0, WORLD.seasonVariance)   (x2)
git show HEAD:src/game/balance.ts      ->  seasonVariance: 1.15
```

Both changes are in the history — `rng.normal` in `2056f5b`, variance 1.15 in `f090142` — and the
reported simulation ran after both. The inspection was reading a checkout from before `f090142`.

### 3.1 Which implementation is authoritative

`rng.normal`, at `seasonVariance: 1.15`. Measured directly over 200,000 draws from committed code:

| | measured | theoretical |
|---|---|---|
| `rng.normal(0,1)` mean | 0.0002 | 0 |
| `rng.normal(0,1)` sd | 0.9987 | 1 |
| \|x\| > 2 | 4.52% | 4.55% |
| \|x\| > 3 | 0.266% | 0.270% |
| max \|x\| | 5.51 | unbounded |
| `rng.gaussian(0,1)` max \|x\| | **0.9813** | hard-bounded at 1.0 |

`rng.gaussian` remains in the codebase and is still used for season ratings. It is a bounded
jitter with **no tails at all** — which is why club seasons were moved off it in v0.4.1, and why
it is flagged again in §17.

### 3.2 Methodology, and reproducing the claim

Reproducing the v0.4.1 harness configuration exactly — 10,000 careers, balanced policy, rotating
positions — from committed code:

```
                      reproduced   V041_REPORT §16.4 claims
won promotion            51.0%              51.0%
suffered relegation      47.5%              47.5%
seasons below top        2.43               2.43
```

All three match. The v0.4.1 report's numbers came from the code that is committed.

Every figure in §16 of this report comes from `V045_SIM.txt`, generated by a single run against
committed code after the Phase 0 changes.

## 4. Player impact changes

**No change needed — it was already implemented.** `playerImpact` has been clamped to
`[-WORLD.impactMinimum, WORLD.impactMax]` = `[-0.35, +1.0]` since v0.4.1.

Measured over 25,000 club seasons:

| | |
|---|---|
| negative | 3.1% |
| zero | 9.7% |
| positive | 87.2% |
| minimum | −0.200 |
| mean | +0.228 |
| maximum | +0.520 |

A backup barely registers either way, because appearance share scales the whole term. The floor is
deliberately a third of the ceiling: a player can help win a league, but nobody relegates a club by
himself.

## 5. Appearance inflation

Real, and the cause was **standing**, not appearances.

`roleValue` accumulated every half-season with no equilibrium — a player even slightly better than
his club gained standing indefinitely — so it saturated at the clamp. Measured before the fix:

- median final `roleValue`: **100** (p90 also 100)
- **67% of all senior seasons** were played at the `icon` tier
- which drew a **99% appearance share**, with p50 and p90 both at 100% of team games

Being the best player at your club is meant to be an achievement, not the resting state of anyone
competent.

### 5.1 Two fixes

**Standing now pulls toward a ceiling** set by how good the player is for his club: level with it
is a starter, ten points clear is a star. He can overshoot on a hot run and gravity brings him
back, which is what makes an exceptional season feel like one.

**`minutesMax` 0.98 → 0.88.** Nobody plays every match of a season once rotation, suspensions,
knocks and cup rest are accounted for. 0.88 of ~42 games is about 37 — a heavy but believable
season for a star.

### 5.2 Before / after

| | before | after |
|---|---|---|
| appearance share, `rotation` | 23% | 29% |
| appearance share, `starter` | 49% | 59% |
| appearance share, `key` | 75% | 80% |
| appearance share, `star` | 91% | 86% |
| appearance share, `icon` | **99%** | **88%** |
| career average share | 83.3% | **74.0%** |
| appearances per season | 33.4 | **29.5** |
| total senior appearances p50 | 576 | **511** |
| Maccabi appearances p99 (GK) | 745 | **679** |
| Maccabi appearances p99 (CM) | 715 | **601** |

700+ Maccabi appearances is now beyond the 99th percentile rather than sitting at it, while the
maximum stays above 400 so legendary careers remain reachable. No recalibration of the Maccabi
Relationship or Legend Score thresholds proved necessary — all their tests still pass.

**Reported rather than fixed:** `icon` is still the most common senior role, because players
out-class their clubs by a wide margin (median peak ability ~81 against Israeli club qualities of
36–76). That is an ability-scale question, not an appearance one, and pushing appearances lower to
hide it would be the wrong fix.

## 6. Design system

Extended rather than rebuilt — the existing CSS already had colour tokens and only three hardcoded
literals.

| group | tokens |
|---|---|
| colour | `--green-primary/deep/bright/glow/wash`, `--black`, `--surface-dark/·/light`, `--line`, `--line-strong`, `--text-primary/secondary/tertiary` |
| accents | `--gold` (legendary only), `--danger` (crisis), `--europe` (abroad), `--neutral` |
| type | `--text-display/hero/h1/h2/h3/body/small/micro`, three leading values |
| space | `--space-1..7` on a 4px base |
| radius | `--radius-sm/md/lg/xl/pill` |
| elevation | `--elev-1/2/3`, `--elev-green`, `--elev-gold` |
| motion | `--t-instant/quick/normal/slow/reveal`, two easing curves |

Every v0.4 token name is kept as an alias, so 200+ existing rules did not all have to change at
once. `prefers-reduced-motion` is handled once at the token level — the timings collapse to 1ms and
a global rule disables animation — rather than per component.

## 7. Global shell

A stadium built from four CSS layers, no images: floodlight bloom from above, pitch-line geometry
at very low contrast (centre circle and halfway line), a touchline glow rising from the bottom, and
a vignette so the edges fall away.

Deliberately at the edge of perception. If you notice it while reading, it is too strong. Nothing
to download, nothing to 404, no external URL to rot.

`env(safe-area-inset-bottom)` on the app padding, so the last action is never under a phone's home
indicator.

## 8. Player Hub

Replaces the v0.4 stat card, which gave all four metrics identical progress bars — which is
precisely why it read as a dashboard.

The hierarchy is now deliberately uneven:

| | |
|---|---|
| name, club | identity, top, largest text |
| **ABILITY** | one focal number in a green plate |
| role | a badge, because it is a status not a quantity |
| trust / maccabism / reputation | compact SVG rings |

Ability counts up when it changes, and only when it changes — a hub that animates from zero every
time you open a screen is noise. Loans show parent club, direction and loan club, because the v0.4
presentation could read as a permanent sale. Abroad recolours the edge stripe and wash blue rather
than repainting the card.

Every club and stage string comes from the v0.4.1 identity module; nothing in the UI assembles team
wording. Verified by screenshot: the academy state reads `מכבי חיפה / ילדים א׳ · בן 12` with no
stale suffix, and the first-team state reads `מכבי חיפה` alone.

## 9. Event presentation

Ten visual variants — coach, match, development, transfer, club, europe, maccabi, crisis, media,
career — each with its own accent, icon and header label, but **one component and one layout**, so
128 events stay coherent.

Derived in `src/ui/eventVisuals.ts` from data the engine already carries (`category`, `clubScope`,
where the player is) rather than added to the event definitions. Two reasons: 128 events would have
needed annotating by hand, and a visual tag living in gameplay data is a tag someone eventually
writes a rule against.

**Context beats category.** An event about Maccabi while the player is elsewhere is a `מהבית`
moment whatever its gameplay category says, because that distinction is one of the things this game
is about.

Importance is derived too: an event that can move the player, open a storyline or place a timeline
beat is a turning point and gets a gold `רגע גדול` flag and a larger title. Everything else stays
quiet, so the flag keeps meaning something.

## 10. Match Moment

A scoreboard strip — minute, club, competition — above `match_moment` events, for senior players
only. A scoreboard above a twelve year old's training session would be worse than none.

The minute is read from the event's own kicker where it states one (`דקה 88`) and otherwise derived
stably from the event id, so it never contradicts the prose and never jitters on re-render.

**Deliberately no opponent and no score.** The engine does not simulate fixtures. Inventing them
would be the game telling the player something untrue, which is exactly the trust problem the last
two versions were about.

## 11. Decision Reveal UX

The v0.4.1 probability engine is unchanged — the invariant that preview and resolver consume one
distribution still holds, and its tests still pass.

What changed is the reading of it. The odds panel was collapsed by default, which is right on a
360px phone but meant **comparing two choices took two taps**. Each choice now carries an
always-visible stacked bar of its outcome split, so the difference between "green and red" and
"green and grey" is visible at a glance; the named percentages stay behind the toggle as the
detail.

Nothing is communicated by colour alone: the bar carries an `aria-label` naming every outcome and
its percentage, and the expanded list names each one with an icon and a label.

The reveal animation is unchanged in behaviour — the engine resolves from the seeded stream first
and the animation only delays showing it — and now inherits the global reduced-motion handling.

## 12. Career Moments

The v0.4 celebration was a small green dialog. It is now the screen: full-bleed, poster typography,
a floodlight sweep that plays **once and settles** rather than looping into a screensaver.

The queue and its gating are unchanged, so frequency is unchanged — these fire only for genuinely
major beats. Making them feel like an occasion therefore costs nothing in pacing. Tap anywhere to
continue, because a moment the player is enjoying should not require hunting for a button.

## 13. Season transitions

The summary leads with the year as a poster line, the club beneath it, then the club's own result,
then the player's numbers — because *"we won the league"* is the headline and *"I played 27 times"*
is the detail underneath it.

The club-season line is looked up by season rather than taking the latest entry, so an academy
season shows nothing rather than last year's finish (v0.4 behaviour, retained).

## 14. Transfer UI

Offer cards show country and the **real** league name (v0.4.1 Phase 5 — `הסרייה א׳`, not a generic
quality bucket), the expected role, the career-level direction and the qualitative hints. Never a
percentage: joining a bigger club as a backup should be a decision the player weighs.

**A bug fixed here shipped in v0.4.1.** The direction chip read
`direction === 'up' ? 'צעד קדימה' : 'צעד אחורה'`, written when `MoveDirection` had three values.
v0.4.1 added `major_up` and `major_down`, and the comparison silently became false for them — so a
Napoli offer to a Maccabi player was labelled **צעד אחורה** while its own hints said
**ליגה חזקה יותר**. TypeScript could not catch it because the comparison stayed valid.

It is now a `Record` over the union, so adding a band fails the build until it is labelled, with
tests asserting no upward move is ever labelled as a step back and that the chip agrees with what
`moveDirection` actually returns.

## 17. Known issues

Stated explicitly.

- **`carried a small club` regressed from 2.4% to 0.4%.** That memory needs player impact above
  `WORLD.breakoutImpact`, and impact scales with appearance share — which Phase 0.3 deliberately
  reduced. The threshold was calibrated in v0.4 against the inflated share and I did not
  recalibrate it when the share changed. A real story beat is now nearly unreachable. The fix is a
  one-number recalibration, but doing it honestly means re-running the 60,000-career simulation,
  which there was not room for tonight.
- **The Legend Score spread by position widened**, from 3.9 points at v0.4.1 to 4.3, with full
  backs now lowest (39.6) rather than centre backs. Explicable — both are defenders in a metric
  weighted toward attacking contribution — but it moved the wrong way.
- **`rng.gaussian` is still used for season ratings** and remains hard-bounded with no tails
  (measured max 0.9813σ). A rating outlier is therefore impossible. This is the same latent shape
  that made relegation impossible before v0.4.1, and it is the first thing I would audit next.
- **`icon` is still the most common senior role.** Players out-class their clubs by a wide margin.
  An ability-scale question, deliberately not addressed by pushing appearances lower.
- **Media-query behaviour is not verified.** The screenshot harness pins the *document* width, and
  width media queries evaluate against the real viewport, which headless Chrome does not set from
  `--window-size`. Layout at a given width is verified; breakpoint behaviour is not.
- **Screens not visually verified:** the new-career/pitch selector, origin/trials, career timeline,
  loan-return, and the ambient Maccabi news presentation. They are unchanged from v0.4.1 and
  inherit the new tokens, but I did not put them in the gallery.
- **Phases not done tonight:** 13–17 (Maccabi relationship / Sami Ofer / ambient news / timeline /
  career story header) received token-level restyling only, not the bespoke presentation the brief
  describes. 20–21 (new career, origin) untouched. 23 (sound) not started. 35 (visual regression as
  a committed suite) — the harness exists and is committed, but there is no baseline-diffing.
- **No `CareerMoment` for the season/stage transitions** described in Phase 10; the existing
  progression card handles them with the new tokens.
- **The gallery is dev-only but ships in the bundle.** It is a few KB behind a query-param check,
  not code-split. Worth splitting if bundle size becomes a concern.

## 19. Recommended v0.5 direction

Not started, as instructed.

1. **Audit the remaining `rng.gaussian` call sites.** Season ratings cannot produce an outlier.
2. **Ability scale.** Median peak ~81 against club qualities of 36–76 is why everyone is their
   club's icon. Fixing it is a balance question with wide reach, and it is the root of the last
   remaining appearance oddity.
3. **Finish the presentation phases 13–17** — the Maccabi relationship, returning to Sami Ofer,
   ambient news and the career timeline are the game's most distinctive content and currently have
   the least distinctive presentation.
4. **Event layouts that can carry a speaker.** The brief's Phase 40 asks that recurring characters
   (agent, manager, mentor) be addable later without a rewrite; the variant system has room for a
   portrait slot but no component for one yet.
5. **A real device pass.** Everything here was verified in headless Chrome at pinned widths.
